# Introducción

En el capítulo anterior aprendimos que no todos los clientes son iguales.

Ahora surge una nueva pregunta.

> **Si ya conocemos a nuestros clientes... ¿qué deberíamos ofrecerles?**

Durante muchos años la respuesta fue sencilla.

Las empresas mostraban exactamente los mismos productos a todos.

Hoy esa estrategia resulta prácticamente imposible.

Piensa por un momento en una tienda en línea.

Puede ofrecer:

- cientos de miles de productos;
- miles de categorías;
- millones de combinaciones posibles.

Mostrar todas las opciones al cliente no facilita la compra.

La hace mucho más difícil.

Aquí aparece uno de los problemas más importantes del marketing moderno.

---

# El problema de tener demasiadas opciones

Podría parecer extraño, pero disponer de demasiadas alternativas puede dificultar la toma de decisiones.

Este fenómeno se conoce como **Choice Overload**.

Imagina entrar a una plataforma de streaming.

Hay miles de películas disponibles.

Después de veinte minutos buscando...

todavía no has elegido ninguna.

Lo mismo ocurre cuando visitamos:

- una tienda en línea;
- una plataforma de música;
- una librería digital;
- una aplicación de cursos;
- una tienda de ropa.

Paradójicamente, más opciones no siempre producen una mejor experiencia.

Muchas veces producen exactamente lo contrario.

---

# Cómo piensa un analista

Cuando observa un catálogo con miles de productos, un analista no piensa:

> ¿Cómo mostramos todo?

Piensa algo muy diferente.

> **¿Cómo mostramos únicamente aquello que probablemente interese a este cliente?**

Ese cambio de perspectiva dio origen a los Recommendation Systems.

---

# ¿Qué es un Recommendation System?

Un Recommendation System es un conjunto de técnicas cuyo objetivo consiste en sugerir productos, servicios o contenido que probablemente resulten relevantes para un usuario.

En otras palabras.

No intenta mostrar todo.

Intenta mostrar lo correcto.

Podemos representarlo de la siguiente manera.

```text
Miles de opciones

↓

Comprender al usuario

↓

Seleccionar pocas alternativas

↓

Mayor probabilidad de interés

↓

Mejor experiencia
```

Observa que el objetivo principal no consiste únicamente en aumentar las ventas.

También busca reducir el esfuerzo que debe realizar el usuario para encontrar aquello que necesita.

---

# ¿Por qué son importantes?

Los sistemas de recomendación generan valor tanto para la organización como para el cliente.

## Para el cliente

- encuentra productos relevantes más rápidamente;
- descubre opciones que probablemente no habría encontrado;
- reduce el tiempo de búsqueda;
- mejora su experiencia.

## Para la organización

- incrementa la conversión;
- aumenta el ticket promedio;
- favorece el cross-selling;
- mejora la fidelización;
- incrementa el tiempo de permanencia.

Por esta razón los Recommendation Systems constituyen una de las aplicaciones más exitosas del Machine Learning.

# Search vs Recommendation

Existe una diferencia muy importante entre buscar y recomendar.

## Search

En una búsqueda el usuario sabe exactamente lo que desea.

Por ejemplo.

Busca:

> "iPhone"

o

> "Hotel en Madrid"

El sistema únicamente devuelve resultados relacionados con esa consulta.

Podemos decir que el usuario dirige el proceso.

---

## Recommendation

En una recomendación ocurre lo contrario.

El usuario no necesariamente sabe qué desea.

El sistema propone opciones utilizando la información disponible.

Por ejemplo.

- También podría interesarte...
- Clientes similares compraron...
- Recomendado para ti...
- Continuar viendo...
- Quizá te guste...

Aquí es el sistema quien guía parcialmente el proceso de descubrimiento.

---

## Una diferencia importante

Podemos resumir ambos enfoques así.

| Search | Recommendation |
|----------|----------------|
| El usuario inicia la búsqueda | El sistema propone opciones |
| Existe una intención explícita | La intención debe inferirse |
| Responde una consulta | Anticipa necesidades |

Esta diferencia parece pequeña.

En realidad representa dos formas completamente distintas de interactuar con un cliente.

---

# Necesidades ocultas (Hidden Needs)

Uno de los conceptos más interesantes en Marketing Analytics consiste en reconocer que los clientes no siempre expresan todo aquello que necesitan.

Imagina una persona que compra una cámara fotográfica.

Probablemente también necesite:

- una memoria adicional;
- una mochila;
- una batería;
- un trípode.

Sin embargo, quizá nunca escriba esas palabras en el buscador.

Un Recommendation System intenta descubrir esas necesidades implícitas.

No porque conozca al cliente personalmente.

Sino porque aprende observando el comportamiento de miles o millones de usuarios similares.

---

# ¿De dónde aprende un Recommendation System?

Toda recomendación depende de información histórica.

Dependiendo del negocio, un sistema puede utilizar datos como:

- compras;
- historial de navegación;
- productos consultados;
- clics;
- valoraciones;
- búsquedas;
- favoritos;
- tiempo de permanencia;
- ubicación;
- dispositivo;
- fecha;
- contexto.

No todas las organizaciones disponen de la misma información.

Lo importante es comprender que cuanto mejor conocemos el comportamiento del usuario, mejores recomendaciones podremos generar.

Recommendation Systems

# Cómo piensa un Recommendation System

Hasta ahora sabemos que un sistema de recomendación intenta responder una pregunta muy sencilla.

> **¿Qué debería mostrarle a este usuario?**

Sin embargo, existen diferentes formas de llegar a esa respuesta.

Podemos pensar en tres estrategias distintas.

```text
¿Qué recomendar?

↓

Observar personas similares

o

Observar productos similares

o

Observar el contexto
```

Cada enfoque intenta resolver exactamente el mismo problema, pero utilizando información diferente.

---

# Collaborative Filtering

El primer enfoque parte de una idea muy intuitiva.

> **Las personas con comportamientos similares suelen tener gustos similares.**

No necesitamos conocer el producto.

Necesitamos conocer a las personas.

Imagina el siguiente escenario.

Carlos y Ana han comprado prácticamente los mismos libros durante los últimos dos años.

Un día Carlos compra un libro nuevo.

Aunque Ana nunca haya visto ese libro, existe una buena probabilidad de que también le interese.

¿Por qué?

Porque ambos han mostrado comportamientos muy parecidos en el pasado.

Ese es el principio del Collaborative Filtering.

---

## Cómo piensa un analista

Un analista no piensa:

> ¿Qué producto recomendaré?

Primero piensa:

> ¿Existen clientes con patrones de compra similares?

Si la respuesta es sí, entonces esos comportamientos pueden utilizarse para generar nuevas recomendaciones.

---

## ¿Cuándo utilizaría Collaborative Filtering?

Este enfoque suele funcionar muy bien cuando existen grandes cantidades de información histórica.

Por ejemplo:

- comercio electrónico;
- plataformas de streaming;
- música;
- cursos en línea;
- librerías digitales;
- supermercados.

En estos casos existen millones de interacciones que permiten identificar patrones colectivos.

---

## ¿Cuándo NO utilizarlo?

Collaborative Filtering presenta algunas limitaciones importantes.

Puede resultar poco adecuado cuando:

- existen muy pocos usuarios;
- apenas hay información histórica;
- continuamente aparecen nuevos productos;
- los usuarios interactúan muy poco.

En estos escenarios suele ser necesario combinarlo con otros enfoques.

---

# Content-Based Filtering

Ahora imaginemos un escenario diferente.

Supongamos que una persona compra una computadora portátil.

En lugar de buscar usuarios similares, el sistema analiza las características del producto.

Podría recomendar:

- otra computadora de características parecidas;
- un monitor compatible;
- un teclado;
- una mochila;
- un mouse inalámbrico.

En este caso no importa demasiado quién compró el producto.

Lo importante son las características del artículo.

---

## Cómo piensa un analista

Aquí la pregunta cambia completamente.

Ya no pensamos:

> ¿Quién es parecido a este cliente?

Pensamos:

> ¿Qué productos son parecidos entre sí?

Esa diferencia es la esencia del Content-Based Filtering.

---

## ¿Cuándo utilizaría Content-Based?

Resulta especialmente útil cuando:

- conocemos muy bien las características de los productos;
- existen pocos datos históricos;
- aparecen nuevos usuarios constantemente;
- queremos explicar fácilmente una recomendación.

Por ejemplo.

> "Te recomendamos este libro porque trata temas similares a los que has leído anteriormente."

---

## Limitaciones

Aunque suele producir recomendaciones relevantes, también presenta una desventaja importante.

Puede generar poca diversidad.

Si una persona compra novelas históricas durante años, probablemente seguirá recibiendo únicamente novelas históricas.

El sistema aprende muy poco sobre otros posibles intereses.

---

# Context-Based Filtering

Existe una tercera forma de pensar.

No observamos únicamente al usuario ni únicamente al producto.

También analizamos el contexto.

La misma persona puede tomar decisiones completamente distintas dependiendo del momento.

Por ejemplo.

Durante el invierno.

Podría interesarse por:

- abrigos;
- calefactores;
- bebidas calientes.

Durante el verano.

Probablemente busque:

- ropa ligera;
- aire acondicionado;
- protector solar.

El usuario sigue siendo el mismo.

Lo que cambió fue el contexto.

---

## Variables de contexto

Dependiendo del negocio pueden utilizarse variables como:

- hora del día;
- día de la semana;
- estación del año;
- ubicación;
- clima;
- dispositivo;
- canal utilizado;
- evento especial.

Estas variables enriquecen considerablemente las recomendaciones.

---

# Sistemas híbridos

En la práctica, pocas organizaciones utilizan únicamente uno de estos enfoques.

Lo más habitual consiste en combinar varios.

```text
Usuario

+

Producto

+

Contexto

↓

Modelo

↓

Recomendación
```

Cada fuente de información compensa las limitaciones de las demás.

Por ejemplo.

Un sistema podría utilizar:

- Collaborative Filtering para descubrir patrones colectivos;
- Content-Based para nuevos productos;
- Contexto para adaptar las recomendaciones según el momento.

---

# El problema del Cold Start

Existe un desafío que prácticamente todos los sistemas de recomendación enfrentan.

Se conoce como **Cold Start**.

La situación es sencilla.

El sistema necesita aprender.

Pero todavía no dispone de suficiente información.

Existen dos casos principales.

## Nuevo usuario

Cuando una persona acaba de registrarse.

Todavía no sabemos:

- qué le gusta;
- qué compra;
- qué consulta.

Resulta difícil personalizar las recomendaciones.

---

## Nuevo producto

También puede aparecer un artículo completamente nuevo.

Como nadie lo ha comprado todavía, el sistema no posee información suficiente para recomendarlo.

---

## ¿Cómo suelen resolverlo las empresas?

No existe una única solución.

Algunas estrategias comunes incluyen:

- recomendar productos populares;
- utilizar información demográfica;
- utilizar las características del producto;
- combinar reglas de negocio con modelos predictivos.

---

# Más allá de la precisión

Existe una idea muy importante que con frecuencia pasa desapercibida.

Un Recommendation System no se evalúa únicamente por su precisión matemática.

También debe generar valor para el negocio.

Por ejemplo.

Una recomendación puede aumentar:

- las ventas;
- la conversión;
- el ticket promedio;
- la permanencia del usuario;
- la fidelización.

En otras palabras.

El mejor algoritmo no siempre es el más complejo.

Es el que produce mejores resultados para la organización.

---

# Cómo evoluciona un Recommendation System

Podemos resumir todo el proceso de la siguiente manera.

```text
Interacciones

↓

Datos

↓

Comprender preferencias

↓

Generar recomendaciones

↓

Nuevas interacciones

↓

Aprender continuamente
```

Observa que el sistema mejora con cada nueva interacción.

Es un proceso de aprendizaje permanente.

---

# Resumen del capítulo

Los sistemas de recomendación representan una de las aplicaciones más exitosas del Marketing Analytics y del Machine Learning.

Su propósito consiste en reducir el exceso de opciones y ayudar a cada usuario a descubrir aquello que probablemente le resulte más útil o interesante.

A lo largo de este capítulo aprendimos tres formas diferentes de construir recomendaciones.

Collaborative Filtering aprende observando personas similares.

Content-Based Filtering aprende observando productos similares.

Context-Based Filtering incorpora además el entorno en el que ocurre la decisión.

Finalmente vimos que, en la práctica, las organizaciones suelen combinar estos enfoques para construir sistemas híbridos capaces de ofrecer recomendaciones más relevantes y robustas.

---

# Ideas clave

- Un Recommendation System busca apoyar decisiones, no únicamente vender productos.
- Existen diferentes formas de generar recomendaciones, dependiendo de la información disponible.
- Collaborative Filtering compara personas.
- Content-Based Filtering compara productos.
- Context-Based Filtering incorpora el entorno de la decisión.
- Los sistemas híbridos suelen ofrecer mejores resultados.
- El éxito de un recomendador debe medirse por el valor que genera para el negocio y para el cliente.
