# El verdadero flujo de un proyecto analítico

Un proyecto de Marketing Analytics normalmente sigue una secuencia similar a la siguiente.

```text
Problema de negocio

↓

Comprensión del negocio

↓

Comprensión de los datos

↓

Preparación

↓

Análisis Exploratorio

↓

Hipótesis

↓

Visualización

↓

Conclusiones

↓

Recomendaciones
```

Observa nuevamente que Python aparece únicamente como una herramienta dentro del proceso.

El protagonista continúa siendo el negocio.

---

# El error más común

Supongamos que recibes un archivo con un millón de transacciones.

El error más frecuente consiste en comenzar inmediatamente con instrucciones como:

```python
df.head()

df.info()

df.describe()
```

Estas funciones son útiles.

Pero todavía no constituyen un análisis.

En realidad únicamente describen la información disponible.

El verdadero análisis comienza cuando intentamos responder preguntas de negocio.

---

## Perspectiva profesional

Un buen analista nunca pregunta primero:

> ¿Qué puedo calcular?

Pregunta:

> ¿Qué necesita saber la empresa?

Esa diferencia cambia completamente el enfoque del proyecto.

---

# Paso 1. Comprender el problema

Antes de abrir el dataset debemos comprender qué decisión desea tomar la organización.

Por ejemplo.

Una empresa informa:

> Las ventas disminuyeron durante los últimos cinco meses.

Esta afirmación representa un síntoma.

Todavía desconocemos la causa.

Nuestro trabajo consiste en descubrirla.

Para ello comenzamos formulando preguntas.

- ¿Perdimos clientes?
- ¿Los clientes compran menos?
- ¿Disminuyó el ticket promedio?
- ¿Cayeron determinadas categorías?
- ¿Ocurrió solamente en algunos mercados?

Estas preguntas determinarán todo el análisis posterior.

---

# Paso 2. Comprender los datos

Una vez comprendido el problema llega el momento de estudiar la información disponible.

El objetivo todavía no consiste en analizar resultados.

Primero debemos responder preguntas como:

- ¿Qué representa cada fila?
- ¿Qué representa cada columna?
- ¿Cuál es la unidad de análisis?
- ¿Existen valores faltantes?
- ¿Qué tipo de variables existen?
- ¿Qué período cubren los datos?
- ¿Cuál es el nivel de detalle?

Esta etapa suele conocerse como **Data Understanding**.

---

## Un concepto fundamental

Uno de los errores más comunes consiste en asumir que una fila representa siempre lo mismo.

No es cierto.

Dependiendo del proyecto, una fila puede representar:

- una venta;
- un producto vendido;
- un cliente;
- una campaña;
- una visita al sitio web;
- una llamada al centro de atención;
- una transacción bancaria.

Comprender esta diferencia evita numerosos errores durante el análisis.

---

# Paso 3. Preparar los datos

Antes de responder preguntas debemos asegurarnos de que los datos sean utilizables.

Esta etapa suele consumir la mayor parte del tiempo de un proyecto.

Las tareas más comunes incluyen:

- eliminar duplicados;
- tratar valores faltantes;
- corregir tipos de datos;
- convertir fechas;
- crear nuevas variables;
- corregir inconsistencias;
- validar reglas de negocio.

En Ciencia de Datos suele afirmarse que:

> **Un modelo excelente nunca compensará datos de mala calidad.**

---

## Perspectiva profesional

En proyectos reales es común dedicar entre el **60 % y el 80 % del tiempo** a preparar los datos.

Construir el modelo suele ser la parte más rápida.

---

# Paso 4. El Análisis Exploratorio de Datos (EDA)

Una vez preparados los datos comienza el verdadero análisis.

El objetivo del EDA no consiste únicamente en generar gráficos.

Busca comprender cómo se comportan los datos.

Por ejemplo:

- identificar tendencias;
- descubrir anomalías;
- detectar patrones;
- encontrar relaciones;
- validar hipótesis;
- identificar oportunidades.

El EDA representa el puente entre los datos y las decisiones.

---

# Formular preguntas antes que gráficos

Un error muy frecuente consiste en generar decenas de gráficos sin un propósito claro.

Cada visualización debería responder una pregunta.

Por ejemplo.

Pregunta:

> ¿Cómo evolucionan las ventas a lo largo del tiempo?

Visualización adecuada:

Una serie temporal.

Pregunta:

> ¿Qué categorías generan mayores ingresos?

Visualización adecuada:

Un gráfico de barras.

El gráfico nunca constituye el objetivo.

Es únicamente una forma de comunicar resultados.

# Convertir preguntas de negocio en análisis

Hasta este punto ya comprendemos el problema, conocemos los datos y los hemos preparado para el análisis.

Ahora debemos responder una pregunta fundamental.

> **¿Cómo transformamos una pregunta de negocio en un análisis concreto?**

El error más común consiste en pensar primero en las funciones de Python.

El enfoque profesional es exactamente el contrario.

Primero definimos la pregunta.

Después elegimos la técnica adecuada.

Finalmente implementamos la solución.

```text
Pregunta

↓

Indicador

↓

Datos

↓

Herramienta

↓

Conclusión

↓

Decisión
```

---

# Pregunta 1
## ¿Quiénes son nuestros mejores clientes?

Una de las primeras preguntas que casi cualquier organización intenta responder consiste en identificar qué clientes generan mayor valor.

Generalmente necesitaremos agrupar la información por cliente y calcular indicadores como:

- ingresos;
- número de compras;
- ticket promedio;
- productos adquiridos.

En Python, este tipo de análisis suele realizarse mediante operaciones de agrupación.

```python
sales_df.groupby("CustomerID")["Sales"].sum()
```

Lo importante no es memorizar la función.

Lo importante es comprender que **estamos respondiendo una pregunta de negocio.**

---

# Pregunta 2
## ¿Cómo evolucionan las ventas?

En muchos proyectos interesa comprender el comportamiento de un indicador a lo largo del tiempo.

Por ejemplo:

- ventas por día;
- ventas por semana;
- ventas por mes;
- ventas por trimestre.

Cuando existe una variable temporal, Python permite resumir la información según diferentes frecuencias.

```python
sales_df.resample(
    "M",
    on="TransactionDate"
)["Sales"].sum()
```

El objetivo no es obtener una tabla.

El objetivo es identificar tendencias, estacionalidad y cambios relevantes.

---

# Pregunta 3
## ¿Cómo comparar diferentes grupos?

En muchas ocasiones necesitamos analizar dos dimensiones simultáneamente.

Por ejemplo:

- país y año;
- categoría y trimestre;
- canal y campaña.

Este tipo de preguntas suele resolverse mediante tablas dinámicas.

```python
pd.pivot_table(
    sales_df,
    values="Sales",
    index="Country",
    columns="Year",
    aggfunc="sum"
)
```

Las tablas dinámicas permiten resumir grandes volúmenes de información de forma muy eficiente.

# Comunicar resultados

Realizar un buen análisis no es suficiente.

También debemos comunicarlo correctamente.

Una buena visualización debe responder una pregunta específica y facilitar la toma de decisiones.

Antes de construir un gráfico conviene preguntarse:

- ¿Qué quiero mostrar?
- ¿Quién verá este gráfico?
- ¿Qué decisión apoyará?

El mejor gráfico no es el más llamativo.

Es el que permite comprender el mensaje en pocos segundos.

---

# Errores comunes

Al comenzar en Marketing Analytics es frecuente cometer algunos errores.

- Analizar datos sin comprender el negocio.
- Confundir exploración con análisis.
- Utilizar demasiados gráficos.
- Optimizar un KPI sin considerar el impacto global.
- Presentar resultados sin recomendaciones.
- Confiar en un único indicador para tomar decisiones.

Un buen analista evita estos errores manteniendo siempre el foco en el problema que intenta resolver.
